# Contributing to Guru2Notion

Thank you for your interest in contributing to Guru2Notion! 🎉

## How to Contribute

### Reporting Bugs

If you find a bug, please create an issue with:
- Clear description of the bug
- Steps to reproduce
- Expected vs actual behavior
- Your Python version and OS
- Relevant log files (sanitize any sensitive data!)

### Suggesting Features

We welcome feature suggestions! Please:
- Check if it's already been suggested
- Explain the use case
- Describe the expected behavior

### Code Contributions

1. **Fork the repository**
2. **Create a branch** for your feature:
   ```bash
   git checkout -b feature/amazing-feature
   ```
3. **Make your changes**
4. **Test thoroughly** with a small export first
5. **Commit with clear messages**:
   ```bash
   git commit -m "Add: feature description"
   ```
6. **Push to your fork**:
   ```bash
   git push origin feature/amazing-feature
   ```
7. **Create a Pull Request**

## Development Guidelines

### Code Style
- Follow PEP 8 conventions
- Use descriptive variable names
- Add comments for complex logic
- Keep functions focused and small

### Testing
- Test with small collections first
- Verify folder structure is preserved
- Check metadata accuracy
- Test error handling

### Commit Messages
- **Add:** New features
- **Fix:** Bug fixes
- **Update:** Changes to existing features
- **Docs:** Documentation only
- **Refactor:** Code restructuring

## Questions?

Feel free to open an issue for any questions!

## Code of Conduct

Be respectful, constructive, and helpful. We're all here to make knowledge migration easier! 🚀
